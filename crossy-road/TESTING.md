## Structure and behavior

Three rules moved from game.js into game-logic.js.

- getMoveTarget computes the proposed column and lane. Columns -3 through 3 and lane 0 are legal. Moves beyond those columns or behind lane 0 return null.
- findSupportingLog returns the first log under the player, or null. The original strict comparison and 0.2 margin are preserved.
- hasVehicleCollision checks street and bridge objects using the original strict comparison and 0.3 margin. Missing lanes and other lane types return false.

game.js imports these functions and continues to handle input, rendering, movement,
score display, game over, and restart. index.html loads game.js as a module.
The package.json inside crossy-road enables ES modules only for this project.
No new validation or bug fixes were introduced during extraction.

The main integration issue was that getLog originally read chicken.position.x
from shared browser state and was called during both landing and river drift.
Both callers now pass the player position and logs explicitly. Existing input
handlers already used addEventListener.

Chrome checks on the original and refactored source covered all four arrow
keys, movement limits, jersey changes, score progression, backward movement
without score loss, vehicle game over, restart, and river log support and drift.
These checks used controlled random values for repeatable street and river lanes.
They establish those exercised behaviors; they do not cover every random level.

## Suite and scope

Run from the repository root with:

```sh
cd crossy-road
node --test
```

The suite has 17 tests across all three functions. It checks both sides of the
board, lane zero, negative columns, exact collision thresholds, empty arrays,
a missing lane, safe lane types, later objects in a list, gaps between logs,
object identity, and preservation of input data.

Rendering, Three.js internals, event dispatch, jersey textures, random level
generation, and animation timing are outside this unit suite. Browser controls
were checked separately. Arbitrary malformed log/car objects and new validation
requirements were excluded because the existing game creates numeric object
positions and lengths and the refactor preserves its existing contract.

The completed suite was committed alone in
